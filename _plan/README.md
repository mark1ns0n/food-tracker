# foodtracker — план: ВЫТЕСНЕН планом super-app

⚠️ Все 44 задачи лежат в `superseded/` — **не выполнять**. Перенесены туда
целиком, без правок, задачей **F01.04** (2026-08-10); до неё они лежали в
`pending/`, и этот README был её опережающей частью, чтобы никто не начал их
делать раньше.

Почему отменены:

- **001–018** (перенос debt-фич из `ban`) — `ban` мигрировал в super-app
  собственным C-треком (`C01`–`C06`, закрыт 2026-07-16), дублировать его фичи
  здесь не нужно. Экономика долга живёт там же и с тех пор ушла далеко вперёд
  (треки `H01`–`H03`).
- **019–044** (собственный sync-бэкенд: Postgres, k8s на mPi5, ArgoCD, GHCR) —
  бэкенд заменён общим B-треком super-app: Rust (axum + sqlx) + PostgreSQL в
  двухузловом K3s, авторизация устройств через DPoP (`B00`–`B05`, `B15`–`B20`,
  закрыты). Второй бэкенд не строим.

Актуальный план миграции foodtracker — один файл
**`../super-app/_plan/pending/F01-food-sync-and-migration.md`** (19 атомарных
задач, фазы 0–4). Фаза 0 (`F01.01`–`F01.04`) выполнена 2026-08-10.

Что это значит для кода здесь: аппка получает CoreSync и вкладку синхронизации,
её существующие данные уезжают в общий event-лог бэкфиллом (`F01.11`), и только
после этого включается первый реальный синк. UI переезжает в оболочку
(`F01.16`–`F01.19`), после чего аппка выводится из эксплуатации.

Каталог фич — `../super-app/_plan/pending/S06`.
